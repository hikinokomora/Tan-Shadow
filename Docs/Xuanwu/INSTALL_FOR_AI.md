# Установка Unity Winter Xuanwu v4.4 — задание для ИИ-агента

Ты работаешь с существующим Unity-проектом. Задача сейчас: переустановить старый skill, сохранив рабочие данные и подключения, проверить инструменты и сразу начать построение окружения на уже готовом Graybox по разделу 8. Это явное разрешение на рабочую копию, но не на платные генерации вне согласованного лимита.

## 1. Обнаружение и резервирование
- Найди переданный `Xuanwu_Complete_v4_4_Optimization_First.zip` и распакуй во временную папку вне Assets. Проверь целостность ZIP, отклони абсолютные пути, `..`, симлинки и коллизии имён при извлечении.
- Найди корень нужного Unity-проекта по `Assets/`, `Packages/manifest.json`, `ProjectSettings/ProjectVersion.txt`. Если найдено несколько проектов, не выбирай случайно. Проверь версию Unity, render pipeline, доступ к Unity/MCP, наличие `.agents/skills` и других механизмов навыков, состояние git (если есть). Не открывай второй Unity Editor на том же проекте одновременно.
- Сними исходные ошибки Console, если Unity доступна. Сохрани список исходных изменений пользователя. Не выполняй git reset/clean, не меняй ветку, не коммить. При существующем skill или файлах с совпадающим именем сравни содержимое, резервируй старую версию вне Assets и активных skills; при конфликте с пользовательскими правками не перезаписывай их автоматически. Не создавай вторую активную копию навыка.

Не меняй глобальные настройки агента, кроме согласованного добавления секции Meshy MCP по разделу 7.
- Сохрани внутреннюю структуру skill без изменений: references, assets, scripts, templates, visual-references, legacy. Не выноси из него файлы, на которые ссылается SKILL.md. `assets/ASSET_DATABASE.json` — единственная каноническая база из 150 карточек; CSV/HTML/MD производные, `Additional_materials` — снимки для просмотра, legacy — архив, не инструкция к исполнению.
- Не копируй HTML, картинки, JSON каталога, Python, шаблоны и весь skill в Unity Assets. Не устанавливай optional SnowBlend.hlsl до отдельной необходимости. В каталоге ссылки на внешние модели, а не сами 3D-файлы; ничего массово не скачивай. Все легально бесплатные поставщики допустимы; CC0 необязателен. Проверяй права, AI usage и условия лицензии перед использованием, при необходимости запрашивай штатную авторизацию без паролей в чате.
- Для Python-скриптов при необходимости создай локальное виртуальное окружение вне Assets, установи зависимости из `scripts/asset-processing/requirements.txt` только если их нет. Не меняй системный Python. Запусти `scripts/validation/test_offline.py` из установленного skill согласно его README; зафиксируй результат, не объявляй тест пройденным без выполнения.

## 3. Unity: проверка после установки
- Прочитай SKILL.md, references/GDD_CONTRACT.md, scripts/README.md и VALIDATION_REPORT.md. Проверь совместимость с фактической версией Unity. Не меняй render pipeline, Packages, Player Settings, контроллер, камеру, бой или существующие сцены ради установки.
- Перед копированием C# сохрани исходный статус компиляции. После копирования инициируй один Refresh/компиляцию через доступный Unity Editor; проверь Console и меню `Tools/Xuanwu/`. Сохрани сгенерированные Unity .meta; не перегенерируй существующие GUID. Если Unity недоступна, запиши NOT RUN. При новых ошибках устраняй только относящиеся к инструментам ошибки, без вмешательства в остальной код; если не удалось — откати только собственные изменения инструментов (сохрани исходники в skill) и укажи блокер.
- Выполни smoke tests по `scripts/README.md` в отдельной тестовой копии проекта/сцене `Xuanwu_Work_Test.unity` при наличии доступного Unity, без изменения оригинальной сцены или TerrainData. Не запускай модифицирующие команды на оригинальном грейбоксе. Шаблоны JSON намеренно требуют реальных значений; не исполняй незаполненные конфигурации. Не сохраняй тестовые объекты в рабочие сцены.
- Подготовь `Docs/Xuanwu/Work/build-state.md` с фактическим состоянием установки. Отчёты tools по умолчанию пишутся в `XuanwuReports/` вне Assets; ссылки на них укажи в build-state. Не добавляй фиктивные метрики.

## 4. Результат установки
Сообщи пользователю корень проекта, путь активного skill, список установленных C# файлов, состояние компиляции и тестов, какие файлы были заменены/резервированы, конфликты/блокеры и путь к каталогу. Отдельно укажи NOT RUN для недоступных проверок. Проверь, что в проекте не появилось дублирующихся классов или активных копий skill. Не объявляй локацию построенной по результатам установки. После успешных проверок переходи к разделу 8 в этой же задаче, без запроса отдельной команды на построение.

## 7. Meshy MCP (v4.4, только установка)
Прочитай `references/MESHY_MCP_SETUP.md` и `references/MESHY_WORKFLOW.md` в установленном Skill. Проверь Node.js, текущий Codex MCP и существующий Unity MCP. С разрешения пользователя добавь официальный Meshy MCP в пользовательскую конфигурацию, не перезаписывая Unity MCP и другие серверы. Пользователь устанавливает ключ локально в `MESHY_API_KEY`, не в чате. Используй TOML examples, перезапусти агент, выполни discovery и read-only balance check. Не запускай генерации даже для smoke test, не покупай кредиты и не меняй сцену. Создай рабочие копии meshy-budget/jobs/generated-assets JSON без потери существующих журналов. В фазе построения (раздел 8) генерация только для дефицита формы после проверки библиотеки, только в отдельно утверждённом бюджете; цвет адаптировать локально. Применяй QA19–QA21. Отдельно сообщи статус Meshy/Unity MCP и доступность общего локального пути. При отсутствии доступа — NOT RUN/BLOCKED, а не выдуманный успех.

## 8. После переустановки — немедленно работать с готовым Graybox
Пользователь уже дал задание построить окружение; не ждать повторной команды. Сохрани старый skill вне активной директории, затем замени его комплектом v4.4 (одна активная версия). Сохрани Unity .meta/GUID, импортированные модели/материалы, файлы Work, существующие отчёты, бюджеты и журналы Meshy, конфигурацию MCP. Новые поля шаблонов и QA22–QA25 добавь в рабочие копии неразрушающим слиянием, не сбрасывай прежние task IDs, списания, резервы, user approvals. Не считать старое разрешение на кредиты действующим, если оно истекло или scope иной. Если лимита нет — не генерируй; один запрос общего лимита при реально недостающей форме, а пока выполняй независимую работу. Не показывай ключи. После замены перечитай фактический установленный SKILL.md, при необходимости перезапусти/перезагрузи агента, убедись что используется новая версия; не дублируй подключение или skill.

1. Прочитай обязательные `GRAYBOX_REBUILD_CONTRACT.md`, `ROUTE_APPROVED.md`, `OPTIMIZATION_FIRST.md`. Используй `ROUTE_APPROVED.png` как актуальную схему. Определи реальную текущую сцену Graybox, сделай резерв и рабочую копию. Измерь готовую тропу/длины/высоты/ширины/якоря, зафиксируй исходное состояние. Не перестраивай маршрут с нуля и не меняй контроллер.
2. Старые шестиугольные Terrain-стены — только условные границы; полностью заменить видимую скальную геометрию и устаревшие коллизии в рабочей копии, сохраняя проходимый пол и исходник. Не облицовывать стены текстурами и не повторять их форму. Скалы из готовых ассетов или прошедших приёмку Meshy-моделей; Terrain для земли и мягких снежных склонов. GDD 1–6 и сплошной подъём 5→6 обязательны.
3. Оптимизация важнее красоты: минимальная достаточная геометрия, роль-бюджеты из `templates/optimization-budgets.json`, простые коллизии, общие материалы, LOD, дешёвый geometry-only Meshy preview лишь при дефиците формы. Сначала 15–25 м эталон нового окружения с clay-проверкой и замерами; затем остальные зоны пакетно. Цвет локально адаптировать, не генерировать из-за цвета. Не тратить кредиты на детализацию, не покупать кредиты, не использовать дорогую модель без отдельного разрешения.
4. После импорта и размещения проверить реальное количество треугольников, LOD, материалы, коллизии и производительность; не принимать превышение порога без локальной оптимизации или согласованного исключения. QA01–QA25 и доказательства. Если Unity/MCP недоступны — не симулировать работу; безопасно выполнить доступные шаги, зафиксировать BLOCKED/NOT RUN и сообщить конкретное необходимое действие. Если Meshy недоступен — продолжать с библиотекой. Сохранять прогресс в build-state.md. Не реализовывать бой, анимацию, динамическую погоду и следы; не изменять исходный Graybox или геймплей. Итог — реальная рабочая сцена и отчёт, а не только план.
