# Производительность
Снять baseline до правок: точная версия/pipeline, платформа, GPU/CPU, resolution, quality, camera, target FPS. Не менять pipeline или Quality глобально. Стартовые цели для среднего PC (не гарантии): 60 FPS = 16.67 ms, 30 FPS = 33.33 ms; согласовать платформу. Unity Profiler standalone Development Build, несколько кадров после прогрева, без Deep Profile; p50/p95 CPU main/render, GPU (если доступно), batches, SetPass, rendered tris, texture memory, total memory. Сравнивать одинаковые условия; 1 зона и вся трасса.
- 2K для near rocks и базовых слоёв, 1K для среднего, 512–1K дальнего плана; mipmaps + подходящая платформе компрессия, проверять normal map. Не тянуть 8K и high-tier Nanite.
- LOD0 только вблизи; стартовые screen-relative пороги 0.5/0.2/0.07, ручной просмотр pop. Уменьшить 100k–2M scans до приемлемой формы на копии. Меши дальнего фона: 0.5–1.5k tris цель, до 3k порог для ridge (см. OPTIMIZATION_FIRST.md); не объединять весь уровень в одну сетку. Объединять только по зоне/материалу после профилирования. Static batching увеличивает память, SRP Batcher и instancing проверять на реальном pipeline.
- Простые collision proxy и TerrainCollider, отсутствие collider на фоне, избегать mesh collider high-poly; не ставить collider на каждый визуальный кусочек снега. Панцирь не static. Без растительности и дорогостоящих VFX.
- `PerformanceAuditor` даёт inventory, НЕ кадр; метрики кадра снять отдельно Profiler + Frame Debugger. Проверить Terrain layers, overdraw, shadow distance, LOD, occlusion в тесных проходах; baking только после утверждения геометрии.
- Если медленно: определить CPU/GPU/VRAM bottleneck, одна локальная правка, повторить тот же контрольный кадр. Не оптимизировать наугад и не обещать FPS.
