# Meshy → Unity: резерв недостающих форм (v4.4)

## 0. Контракт
Маршрут готов. Восстановить природные границы с нуля, сохраняя измеренную тропу, шесть зон и все требования `GRAYBOX_REBUILD_CONTRACT.md`. Meshy — второй источник геометрии после готовых моделей, а не замена всему каталогу. Никаких генераций во время установки. Без разрешённого бюджета или доступа — BLOCKED для генерации, но продолжать независимые участки. Не менять контроллер, не строить босса и не генерировать всю карту целиком.

## 1. Когда обращаться к Meshy
1. Зафиксировать геометрический пробел: зона, роль (wall/macro/corner/overhang/edge/seam/background), world bounds в метрах, ориентация, силуэт, разломы, направление слоёв, нужные поверхности, пределы камеры/маршрута. Не использовать форму старых стен. Измерить свободное пространство по реальной тропе.
2. Найти пригодную форму в локальных ассетах, ранее одобренных Meshy-префабах и JSON-каталоге. Проверить не более двух новых кандидатов на роль. Допустимы разумные rotation/scale и композиция нескольких совместимых моделей; не растягивать до визуального разрушения. Сравнивать геометрию в нейтральном материале: цвет не влияет на решение о генерации. Проверить лицензии и допустимость обработки. Неподходящий коричневый цвет сам по себе никогда не считается отказом: использовать K2/K3 и существующие материалы.
3. Если ни один допустимый кандидат не решает **форму**, заполнить запись в `Docs/Xuanwu/Work/meshy-jobs.json` (шаблон в `templates/`). Сохранить причины отказа по форме, проверенные ID, размеры и запрос. Не пытаться генерировать новую форму ради разнообразия без геометрической необходимости. Одна задача — один переиспользуемый модуль, не целая локация.
4. Проверить баланс, модель, цену по актуальным docs, остаток пользовательского лимита, наличие незавершённых или ранее успешных задач с тем же shape_key. Если достаточно — агент сам отправляет запрос без повторного согласования в рамках уже утверждённого бюджета. При нулевом лимите попросить один общий лимит на сессию; не покупать кредиты автоматически.

## 2. Подключение и вызовы
Установка: `MESHY_MCP_SETUP.md`. Официальный сервер Meshy и Unity MCP/Editor — два отдельных интерфейса одного агента. Meshy не импортирует сцену в Unity сам. Использовать реальные имена инструментов и их текущие schemas после discovery; параметры ниже — намерения/поля API, не выдуманные MCP сигнатуры.

| Операция | Официальный инструмент (имя проверено 26.11.2026) |
|---|---|
| Баланс | `meshy_check_balance` |
| Меш из текста (без текстур) | `meshy_text_to_3d` |
| Меш из разрешённого изображения, если текст не описывает форму | `meshy_image_to_3d` |
| Проверка задачи | `meshy_get_task_status` |
| Поиск ранее отправленной задачи | `meshy_list_tasks` |
| Скачивание результата | `meshy_download_model` |

По умолчанию использовать Text to 3D preview. Если нужно изображение: только разрешённые для такой обработки собственные эскизы/схемы отдельной модели; не передавать приватные скриншоты проекта или чужие игровые изображения в сервис без соответствующих прав и разрешения. Для Image to 3D отключить текстурирование (`should_texture: false`, если доступно в schema). Не использовать `meshy_text_to_3d_refine`, `meshy_retexture`, платный remesh/convert/resize/UV, генерацию 2D, rig/animate по умолчанию. Сначала использовать локальные инструменты и существующие материалы.

## 3. Параметры и промпты
- Предпочтительный формат FBX (native Unity), `target_formats: ["fbx"]` если поддерживается. GLB только при уже установленном совместимом импортере либо локальной конвертации Blender; не ставить автоматически новый Unity package. OBJ резервный вариант после проверки UV и масштаба.
- Начать с экономичного `meshy-t2.5` (smart-topology, треугольники, целевой polycount по роли, обычно 500–5000 треугольников, см. OPTIMIZATION_FIRST.md) или `meshy-6-lite` для простых форм; для сложного hero-cliff — `meshy-7.1`, standard geometry resolution, только при обязательном дефиците формы после дешёвого варианта, отдельном согласовании и достаточном бюджете. Сверить наличие и цену моделей в текущей версии; не отправлять несовместимые поля. Для smart-topology не требовать should_remesh; standard model target_polycount применяется с should_remesh, если поддерживается. Не использовать устаревшее meshy-7 или ultra_mode.
- Параметры полигонов — стартовые ориентиры, а не измеренный лимит проекта. Определить реальное значение по видимому размеру, дистанции, профилированию. Масштаб задавать и проверять в Unity по bounds, не полагаться на размер из AI prompt.
- Промпт до 800 символов; одно изолированное природное изделие, asymmetrical silhouette, irregular fractured planes, broad angular layers, geological coherence, no built structures, no loose obstacle rocks, no ground plane, no scene/background, no plants, no snow baked into mesh unless dedicated snow module. Neutral untextured geometry. Не требовать конкретный цвет породы. Перед отправкой обязательно прочитать `MESHY_PROMPT_GUIDE.md`, заполнить `templates/meshy-shape-request.json` и выбрать одну строку из `templates/meshy-prompt-library.json`. `MESHY_PROMPTS.md` — читаемая библиотека. Ориентир 150–400 символов, 800 — текущий лимит API; применять более строгий лимит, если MCP требует.

## 4. Асинхронный цикл и отказоустойчивость
- До вызова записать shape_key, параметры, estimated_credits, UTC timestamp, состояние SUBMITTING. После ответа немедленно сохранить task ID и состояние PENDING/IN_PROGRESS. Запись не должна содержать API key, signed URL или приватные данные.
- По умолчанию максимум 1 активная задача, максимум 2 попытки генерации на shape_key в пределах общего бюджета. Пока Meshy выполняет задачу, агент продолжает независимые участки в Unity, аудит материалов, подбор ассетов и подготовку placement. Не закрывать пользовательскую сессию с обещанием фоновой работы: если продолжение невозможно, вернуть сохранённый ID/статус и возобновить по журналу в следующей сессии. Если инструмент синхронно блокирует на время генерации, сохранить ID при первой возможности; не создавать параллельный дубликат.
- Если инструмент предоставляет неблокирующий режим, использовать его. Poll `meshy_get_task_status` по рекомендованному интервалу сервиса и rate limit (не tight loop); ориентир 20–30 секунд только если API не задаёт иной интервал. После тайм-аута не создавать новую задачу; восстановить существующий ID или сверить `meshy_list_tasks`/историю в Meshy. Если результат создания неизвестен — `UNKNOWN_SUBMISSION`, удержать резерв кредитов до сверки. 401/402 — блокер авторизации/лимита; 429 — следовать Retry-After; 5xx/тайм-аут создания — не повторять POST автоматически.
- SUCCEEDED → скачать указанный формат через `meshy_download_model` в staging вне Assets, проверить файл. Подписанные URL временны, при истечении запросить status заново, не генерировать повторно. FAILED/CANCELED — зафиксировать причину и фактическое списание; не считать возврат гарантированным. Не удалять завершённую задачу для «возврата» кредитов. Не выполнять бесконечные попытки, не менять API backend молча.

## 5. Импорт в Unity: точный порядок
1. Сохранить исходный скачанный файл в `Docs/Xuanwu/Work/MeshyStaging/<asset-id>/` или внешнем локальном кеше, hash SHA-256. Проверить формат и содержимое; не импортировать архивы, исполняемые файлы и скрипты от внешних сервисов. `scripts/asset-processing/stage_meshy_fbx.py` проверяет FBX и безопасно копирует его (dry run по умолчанию). Не копировать API key в проект.
2. Проверить модель в локальном просмотрщике/Blender либо тестовой сцене: форма с 3–4 ракурсов, отсутствие лишнего пола/отдельных объектов, вывернуть неверные normals, проверить UV, отверстия/самопересечения и silhouette. Для cliff backface важна реальная видимость с обеих сторон; не требовать watertightness там, где она не нужна. Отбраковать непригодную форму до работы с материалом. При необходимости один локальный repair, не деформирующий силуэт.
3. Перенести FBX в `Assets/XuanwuGenerated/Meshy/<asset-id>/Source/model.fbx` через helper или ручное безопасное копирование. В существующем Unity MCP/Editor инициировать один AssetDatabase.Refresh для группы готовых файлов. Проверить `AssetDatabase.LoadAssetAtPath<GameObject>` или доступный equivalent. Отдельный Meshy API не имеет доступа к Unity scene. Не открывать второй Unity Editor. Если нет Unity MCP, использовать уже разрешённые editor tools; если нет доступа ни к Unity, ни к Editor — NOT RUN, не утверждать, что импорт завершён.
4. В ModelImporter/Inspector проверить scale factor, axes, mesh normals, UV, material import (не создавать лишние дубликаты), отключить animation/rig для статической породы. Установить 1 Unity unit = 1 м; подогнать размеры по world bounds, без изменения исходной тропы. Сделать prefab в `Assets/XuanwuGenerated/Meshy/<asset-id>/Prefabs/`. Оригинальный FBX сохранить. Сохранить Unity .meta/GUID.
5. Применить общие `Rock_Dark`/`Rock_Cold` и принятые PBR-материалы, проверить UV либо world/triplanar mapping если уже доступен. Не накладывать материал на старые стены. Материалы снега, transition meshes и снеговые маски — по `MATERIAL_GUIDE.md`. LOD0 под фактический бюджет; LOD1/LOD2 локальной децимацией (например ~50%/~15–25% tris, только если silhouette сохранён), корректные переходы LODGroup. Для стен отдельные простые статические collider proxies или упрощённый MeshCollider; не закрывать тропу, провалы или навес. Не требовать Rigidbody для статических скал.
6. Audit selected models → проверить actual triangles, material slots, texture memory, bounds, LOD, collider. Разместить готовый prefab через `RockPlacementTool`/Unity MCP в рабочей копии (по конфигу placement). Clay/solid view + вид сверху + реальная камера. Сверить route validator, Play Mode и сохранение длины/высот. Не перекрывать проход 5→6. Никаких новых препятствий из камней на обязательной тропе.
7. Только после успешной приёмки статус APPROVED; добавить в рабочую библиотеку `meshy-generated-assets.json` с source/task ID, hash, license/plan at generation, prompt, family/role, bounds, actual tris, prefab path/GUID и QA evidence. Каталог 150 внешних ссылок остаётся неизменным, а рабочая локальная библиотека индексируется отдельно и проверяется прежде новых генераций. Повторное использование не требует новых кредитов. Не распространять платный исходник вне проекта без проверки прав.

## 6. Бюджет и остановка
Отдельно считать кредиты Codex и Meshy. По официальному README на дату проверки дешёвая сетка стоит ориентировочно 5 кредитов, standard 7.1 — 20; текстурирование, высокое разрешение и постпроцесс могут стоить дополнительно. Сверить актуальный тариф непосредственно перед задачей; не обещать цену. Предложение стартового лимита: 40 кредитов Meshy на этап, но **не активировать его без явного согласия**. Шаблон по умолчанию содержит 0. Баланс веб-плана не гарантирует доступ к API; для API требуется подходящий план и ключ. Не покупать подписки и кредиты. Резервировать estimated credits на все незавершённые и неопределённые задачи; если списание не известно, не освобождать резерв до сверки. Проверять сумму фактического/зарезервированного бюджета перед каждым платным вызовом. Максимум две попытки на один модуль; после второй неудачи использовать другой готовый допустимый ассет, либо оставить помеченный блокер (не примитивную финальную стену).

## v4.4 — обязательная оптимизация
См. `OPTIMIZATION_FIRST.md`: техническая пригодность важнее красоты. Перед генерацией выбрать роль и бюджет из `templates/optimization-budgets.json`, после импорта измерить реальные tris каждого LOD, material slots, collision proxy, число копий и сохранить `asset-optimization-report.json`. Не размещать тяжёлую модель до оптимизации. Неподходящий цвет и недостаток микродеталей не основания для повторного запроса. Дорогие модели и превышение review cap требуют отдельного согласования, не только наличия кредитов. QA22–QA25.
