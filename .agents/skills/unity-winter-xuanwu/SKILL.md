# Xuanwu Winter · v4

**Goal:** real Unity environment scene, not a simulated report. Follow user/GDD first; preserve greybox and game code. Read `references/GDD_CONTRACT.md` once. No jumping, climbing, obstacle rocks, foliage, buildings or extra hub. Order: tunnel → ravine/bypasses → paw → slope (left wall/right drop) → head (~5m) → neck → separate shell → summit. No combat, shake, weather or tracks system now. Existing controller/camera unchanged.

## Workflow (progressive disclosure)
1. **Audit**: use `scripts/README.md` and SceneAuditor, read state first if resuming. Capture actual Unity version/pipeline, scene, controller radius/height/slope/roll and camera, anchors, protected gaps, baseline. Work on explicit Xuanwu_Work scene and copied TerrainData. Review git diff, no commits without request. Run tool smoke tests on scratch scene before actual edits. If cannot connect to Unity, report NOT RUN; don't claim scene built.
2. **Geometry**: read `TERRAIN_RECIPES.md`, `LEVEL_COMPOSITION.md`. Correct floor and outline first. Terrain for continuous slopes, mesh for cliffs/overhangs, separate shell. Keep topology, gaps and anchors. Build routes from measured coordinates, not guessed. Use route validator plus real Play Mode walk/roll and camera in both directions. Do not tweak movement to hide geometric problems.
3. **Art slice**: read `ART_DIRECTION.md`, `MATERIAL_GUIDE.md`. Pick one geological family. Reuse local assets first. Query canonical DB using `python scripts/asset-processing/catalog.py --role wall --family layered --limit 5` or filter JSON. All legally free providers allowed; CC0 not a priority. Require current price, mod rights, AI scope and attribution before acquisition. NoAI/unknown not approved. Ask for normal sign-in, never passwords. K2 warm brown/ochre requires desaturation+darkening+cool tone; K3 remove moss/plants; K4 clean snow; K5 muted ice. No two incompatible geologies. Import 3–5 rock shapes, 2–3 snow shapes, 2–3 materials initially. Build 15–25m example with neutral material lab and clear seam; only then expand.
4. **Expand**: select roles (macro, wall, corner, overhang_candidate, edge_candidate, snow_slope, seam, background, rock_material, snow_material), use authored placement config and editor tools. No scatter along path. 2–3 low cost background ridges. Reuse prefab and material, verify local zone. A candidate tag is not geometry proof.
5. **QA**: `PERFORMANCE_GUIDE.md`, `QUALITY_CHECKLIST.md`. Inventory is not visible tris or GPU timing. Real profiling same hardware/camera/settings, QA01–QA15 statuses and evidence. Fixed six frames and top. Report path, files, source manifest, blockers, tests not run. No claims of optimization without measurement.

## Cost guard
Read one short doc per phase, not all files. `assets/ASSET_DATABASE.json` canonical; CSV/HTML/MD generated, legacy only for audit. Use `templates/build-state.md` after each phase. Max 2 candidates per role, 2 rounds blockout/slice, one batch per zone, one final fix. Two failed attempts → fallback or blocker. Use the editor tools rather than repeatedly scripting individual actions. Do not install extra packages, change project-wide graphics, import all candidate packs, or do paid purchases. Preserve original data and other contributors' work. If geometry topology must change or permission is missing, ask only that decision. `DECISION_TREE.md` for ranking and fallback.

## Tools
12 explicit Unity menu commands, no runtime callbacks. `scripts/README.md` for configs, guardrails and smoke tests. All C# sources need compile and scratch checks on target Unity before use. `recolor.py` local base-color transform; `catalog.py` query/rebuild. Optional HLSL snow blend only if necessary. Use `templates/` for actual values; route config deliberately invalid until filled. See `VALIDATION_REPORT.md` for verification status.
