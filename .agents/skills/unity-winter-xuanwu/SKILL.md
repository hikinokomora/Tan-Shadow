# Xuanwu Winter · v4.4

**Goal:** real Unity environment scene, not a simulated report. Follow user/GDD first; preserve the original greybox as a backup and preserve game code; rebuild all visible rock boundaries from ready-made or approved Meshy-generated mesh assets in the working copy. Read `references/GRAYBOX_REBUILD_CONTRACT.md` FIRST, then `references/GDD_CONTRACT.md` and `references/ROUTE_APPROVED.md` once; the latter is the authoritative six-zone layout. No jumping, climbing, obstacle rocks, foliage, buildings or extra hub. Order: 1 tunnel → 2 ravine (single route) → 3 paw → 4 slope (left wall/right drop) → 5 head (~5m) → 6 separate shell via a continuous walkable head/neck-to-shell slope → heart. No combat, shake, weather or tracks system now. Existing controller/camera unchanged.

## Workflow (progressive disclosure)
1. **Audit**: use `scripts/README.md` and SceneAuditor, read state first if resuming. Capture actual Unity version/pipeline, scene, controller radius/height/slope/roll and camera, anchors, protected gaps, baseline. Work on explicit Xuanwu_Work scene and copied TerrainData. Review git diff, no commits without request. Run tool smoke tests on scratch scene before actual edits. If cannot connect to Unity, report NOT RUN; don't claim scene built.
2. **Geometry**: read `TERRAIN_RECIPES.md`, `LEVEL_COMPOSITION.md`. The existing greybox route is already laid out: capture its real centerline, per-zone lengths, elevations, widths and anchors; keep topology, gaps and gameplay anchors. In the working copy remove/disable old primitive cliff walls AND their obsolete colliders (shared Terrain: preserve/reconstruct the safe floor). Never use the old wall shape as an art reference or cover it with texture and a few meshes. Build new cliffs, overhangs and edges exclusively from compatible ready-made or approved Meshy-generated 3D assets, including visible background rocks. Terrain only for walkable ground/smooth snow slopes; separate shell. Build routes from measured coordinates, not guessed. Use route validator plus real Play Mode walk/roll and camera in both directions. Do not tweak movement to hide geometric problems.
3. **Art slice**: read `ART_DIRECTION.md`, `MATERIAL_GUIDE.md`. Pick one geological family. Reuse local assets first. Query canonical DB using `python scripts/asset-processing/catalog.py --role wall --family layered --limit 5` or filter JSON. All legally free providers allowed; CC0 not a priority. Require current price, mod rights, AI scope and attribution before acquisition. NoAI/unknown not approved. Ask for normal sign-in, never passwords. K2 warm brown/ochre requires desaturation+darkening+cool tone; K3 remove moss/plants; K4 clean snow; K5 muted ice. No two incompatible geologies. Import 3–5 rock shapes, 2–3 snow shapes, 2–3 materials initially. Build 15–25m example with new asset geometry and clear seams; verify clay/solid view with old walls absent, then materials and actual camera; only then expand. If no suitable SHAPE after local/cache/catalog search (max 2 candidates), use `references/MESHY_WORKFLOW.md`; never generate because of color. Read `references/MESHY_MCP_SETUP.md` for connection. Before any generation read `references/MESHY_PROMPT_GUIDE.md` and select one role from `templates/meshy-prompt-library.json`; fill a measured shape brief (`templates/meshy-shape-request.json`). One isolated geometry-only prompt; no color-driven generation. Preview geometry only, save task IDs, download FBX and import/QA in Unity; use approved budget only. While a task is pending, work on independent zones if tools permit. Reuse approved generated prefabs.
4. **Expand**: select roles (macro, wall, corner, overhang_candidate, edge_candidate, snow_slope, seam, background, rock_material, snow_material), use authored placement config and editor tools. No scatter along path. 2–3 low cost ready-made or approved Meshy-generated background ridge assets; no procedural visible rock boundaries. Reuse prefab and material, verify local zone. A candidate tag is not geometry proof.
5. **QA**: `PERFORMANCE_GUIDE.md`, `QUALITY_CHECKLIST.md`. Inventory is not visible tris or GPU timing. Real profiling same hardware/camera/settings, QA01–QA25 statuses and evidence. Fixed six frames and top. Report path, files, source manifest, blockers, tests not run. No claims of optimization without measurement.

## Cost guard
Read one short doc per phase, not all files. `assets/ASSET_DATABASE.json` canonical; CSV/HTML/MD generated, legacy only for audit. Use `templates/build-state.md` after each phase. Max 2 candidates per role, 2 rounds blockout/slice, one batch per zone, one final fix. Two failed attempts → fallback or blocker. Use the editor tools rather than repeatedly scripting individual actions. Do not install extra packages, change project-wide graphics, import all candidate packs, or do paid purchases (Meshy generation is a separate, explicitly capped exception). Preserve original data and other contributors' work. If geometry topology must change or permission is missing, ask only that decision. `DECISION_TREE.md` for ranking and fallback.

## Tools
12 explicit Unity menu commands, no runtime callbacks. `scripts/README.md` for configs, guardrails and smoke tests. All C# sources need compile and scratch checks on target Unity before use. `recolor.py` local base-color transform; `catalog.py` query/rebuild. Optional HLSL snow blend only if necessary. Use `templates/` for actual values; route config deliberately invalid until filled. See `VALIDATION_REPORT.md` for verification status.

## v4.4 — Optimization First (приоритет над прежними числовыми целями)
**Оптимизация выше красоты и мелкой детализации.** Прочитай `references/OPTIMIZATION_FIRST.md` и `templates/optimization-budgets.json` перед выбором/генерацией модели. Проходимость, маршрут, лицензии и обязательный силуэт — условия допуска. Использовать lowest adequate triangle budget, дешёвый geometry-only preview, без текстур/Ultra; проверять фактическую геометрию, LOD, material slots, коллизии и runtime-метрики до массового размещения. Сохранять `asset-optimization-report.json`; QA22–QA25 обязательны. Более дорогая модель или превышение порога — только по отдельному согласованию, в разрешённом лимите. Если Meshy недоступен или лимит нулевой, работать с готовыми моделями в независимых зонах.
