# Meshy MCP + Unity: установка в Codex (Windows / другие ОС)

Установка без генерации. Официальный пакет `@meshy-ai/meshy-mcp-server` из npm; исходники https://github.com/meshy-dev/meshy-mcp-server. Не устанавливать неофициальный одноимённый мост. Требуется Node.js >=18 по README; предпочесть поддерживаемую LTS-версию. Проверить `node --version`, `npm --version`, `codex mcp list`. Не менять существующий Unity MCP. Проверить версию пакета по официальному npm/repository, выбрать проверенную версию и при необходимости зафиксировать её вместо плавающего latest. Не запускать произвольный сторонний installer.

1. Пользователь создаёт API key на https://www.meshy.ai/ (Developer Platform → API Keys) и вводит его в локальное защищённое окружение `MESHY_API_KEY` вне репозитория. Не просить ключ, пароль или signed URLs в чате, не записывать их в SKILL/AGENTS/config проекта/отчёты. Убедиться, что процесс Codex наследует переменную; после изменения окружения перезапустить Codex. Не печатать значение ключа. Доступ к веб-приложению сам по себе не гарантирует доступ к API.
2. В пользовательский `~/.codex/config.toml` (Windows обычно `%USERPROFILE%\.codex\config.toml`, с учётом CODEX_HOME) добавить только одну секцию Meshy, сохранив остальное. Шаблон `templates/meshy-codex-windows.toml.example`, `templates/meshy-codex-unix.toml.example`. При существующей секции проверить её и не дублировать. Изменение пользовательских настроек и установка пакета — с разрешением пользователя; не распространять ключ. Для Windows cmd /c npx, для Linux/macOS npx. `env_vars` пробрасывает значение из окружения, а не сохраняет секрет. Если версия Codex не поддерживает такое поле, сверить официальную инструкцию и использовать защищённую локальную настройку; не класть ключ в командную строку/историю.
3. Перезапустить клиент, `codex mcp list`, затем /mcp (если есть в интерфейсе). Discovery текущих MCP schemas; проверить наличие `meshy_check_balance`, `meshy_text_to_3d`, `meshy_get_task_status`, `meshy_download_model`, `meshy_list_tasks`. Выполнить только read-only `meshy_check_balance`. При отказе не генерировать; сообщить 401/402/сеть/проблему версии без секретов. Проверить доступность Unity MCP (scene inspection/asset import) отдельно, не изменяя сцены. Если они работают в разных средах, проверить общий путь к файлу или разрешённое копирование: скачанный FBX должен быть физически доступен Unity. Не считать, что путь на удалённом MCP автоматически существует на ПК.
4. Создать рабочие копии `meshy-budget.json`, `meshy-jobs.json`, `meshy-generated-assets.json` в `Docs/Xuanwu/Work/`, не перезаписывать прежние журналы. Default budget = 0. В отчёте установки указать MCP discovery, balance check status, Unity read-only status и ограничения; никаких платных запросов и изменений локации.

Если MCP недоступен, официальная Meshy CLI использует тот же API (https://docs.meshy.ai/en/api/cli). Допустим как явно разрешённый запасной путь, не как параллельный второй запрос: тот же task ID и бюджет. Не устанавливать CLI и не отправлять API запрос без разрешённого доступа. Для Codex локальные настройки MCP описаны здесь: https://learn.chatgpt.com/docs/extend/mcp . ChatGPT web не использует пользовательский локальный Codex config. Для данной задачи нужен агент, который реально имеет доступ к Unity-проекту.

## Дополнение v4.3: промпты Meshy
При дефиците формы перед генерацией обязательно использовать `MESHY_PROMPT_GUIDE.md` и библиотеку `MESHY_PROMPTS.md`. Измерить слот, сохранить brief и причины отказа кандидатов, выбрать один объект и проверенные MCP-параметры. Не генерировать из-за цвета, не отправлять общие кадры уровня. В QA19 приложить brief, фактический prompt либо разрешённые референсы; в QA20 — clay-кадры и соответствие слоту; в QA21 — журнал попыток. Установка не разрешает генерацию.


**v4.4:** установка не тратит кредиты; после проверки инструментов пользователь разрешил построение окружения в рабочей копии Graybox. См. INSTALL_FOR_AI.md, раздел 8.
