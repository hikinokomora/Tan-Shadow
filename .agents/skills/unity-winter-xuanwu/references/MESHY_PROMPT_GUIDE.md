# Meshy Prompt Guide — Сюаньу / Fjell 652 · v4.4
Проверено по официальной документации 26.11.2026. Это правила для агента, не разрешение на расходы или передачу файлов. При конфликте первичны GRAYBOX_REBUILD_CONTRACT, GDD_CONTRACT, ROUTE_APPROVED и MESHY_WORKFLOW. Данная глава уточняет только создание запросов.

## 1. Что подтверждено Meshy, а что является правилом проекта
Официальные рекомендации [1–4]: назвать один предмет в начале, описать его свойства, художественный стиль и техническое назначение; ключевые признаки важнее длины; длинные противоречивые запросы вызывают отклонение от замысла. Для игровых объектов выбирать Smart Topology, не перегружать деталями. Нежелательные элементы исключать короткими фразами в самом тексте. API Text-to-3D [5] принимает до 800 символов. Preview строит геометрию; refine выполняет текстурирование. MCP вызывает API, а не обязателен переход через веб-чат Meshy Agent. [6]

Наши решения: английские промпты; рабочий ориентир 150–400 символов (не лимит API); 3–5 главных геометрических признаков; один природный модуль; реалистичная крупная слоистая порода, нейтральная геометрия; никаких требований к цвету, туману, кинематографичности или освещению в запросе на меш. Для снега — отдельные формы при необходимости. Никаких построек, растительности, рассыпанных камней на тропе. Не просить копировать конкретные модели Battlefield, только использовать общий характер геологии как ориентир. Не генерировать колосса, панцирь, голову, лапу, бой или весь уровень в рамках окружения.

## 2. Сначала измерить недостающую форму
1. Найти слот в рабочей сцене, записать зону, роль, world bounds (W/H/D в метрах), направление видимой грани, сторону стыка, положение основания/верха, максимальный вынос, неприкосновенный объём пути и камеры. Размеры брать из реальной сцены, не со схемы.
2. Проверить одобренные локальные меши, Meshy-кеш и каталог, не более двух новых кандидатов на роль; сравнить в clay/solid view без влияния цвета. Если форма подходит, использовать её (в том числе коричневую), привести к общей гамме локально. Сначала разумно проверить композицию готовых модулей. Не использовать неразрешённые ассеты.
3. Если формы нет, записать проверенные ID и причины отказа в рабочий журнал; заполнить `meshy-shape-request.json` на каждый shape_key (копия шаблона). Определить главный силуэт и 3–5 признаков, которые не могут быть заменены текстурой.
4. До отправки сверить бюджет, права, актуальную схему MCP и отсутствие дубликата. Не генерировать во время установки. Не отправлять содержимое проекта или чужие изображения без разрешения. Утверждённая схема — планировка для агента, не картинка для Image-to-3D.

## 3. Конструктор текстового запроса
Формула проекта: **один объект → крупная форма/пропорции → геологические грани и силуэт → ключевой функциональный признак → реалистичный игровой меш и краткие исключения.**

`Single [role], [dominant silhouette/proportions], [2–3 geological shape features], [critical interface or clearance], realistic game-ready mesh, no [1–3 specific unwanted features].`

Ставить самое важное сразу за названием объекта. Не соединять противоречия: smooth cliff + jagged cliff; very thin + solid massive; cartoon + realistic. Не перечислять всё, что видно на скриншоте уровня. Не просить десять отдельных камней, снежную тропу и горы в одном запросе. Если основной признак — навес, не добавлять общий запрет на навесы. Не требовать симметрии для природной скалы. Слово game-ready — ориентир, а не доказательство оптимизации. Количество треугольников задаётся параметрами инструмента, не словами в промпте. Фразы `no ground plane`, `no detached pieces`, `no stairs` выбирать по задаче; универсальная длинная строка запретов не нужна. Не выдумывать отдельный `negative_prompt`, `art_style` или `seed` в MCP: использовать лишь реально объявленные поля. Не путать texture_prompt с геометрическим запросом.

Пропорции лучше описывать сравнительно (wide and shallow, tall and thick, short projection); при необходимости указать приблизительное отношение W:H:D, без обещания точного размера. Координаты, требуемые зазоры, точные размеры, pivot и разрешённый уклон остаются в локальном brief. Meshy может не выдержать пропорции; проверить и корректировать в Unity по bounds; не растягивать до разрушения геологии. Если требуется точный угол стыка, использовать измерение в локальном тесте, а не считать градусы гарантированными промптом.

## 4. Выбор канала и параметров
| Ситуация | Действие |
|---|---|
| Недостающий обычный модуль, понятный по тексту | `meshy_text_to_3d`, геометрический preview |
| Сложный силуэт, особый навес/стык, есть разрешённый изолированный референс | `meshy_image_to_3d`, `should_texture: false` |
| Одного вида недостаточно, есть согласованные разные виды того же объекта | `meshy_multi_image_to_3d`, проверить совместимость модели и стоимость; `should_texture: false` |
| Цвет не совпадает | Не обращаться в Meshy; локальный материал/коррекция |
| Точное позиционирование и проход | Измерение и размещение в Unity, не генерация сцены |

Пример **REST-полей**, не выдуманная сигнатура MCP (проверить discovery):
```json
{"mode":"preview","prompt":"Single alpine cliff wall module, tall broad fractured planes, thick rock volume, asymmetric layered silhouette, realistic game-ready mesh, no ground plane.","model_type":"smart-topology","ai_model":"meshy-t2.5","topology":"triangle","target_polycount":4000,"target_formats":["fbx"]}
```
В MCP preview может задаваться самим инструментом. Передать только разрешённые его текущей схемой поля; не добавлять `mode`, если инструмент сам выбирает preview. Если формат нельзя выбрать при создании, запросить FBX при скачивании. T2.5 предпочтителен для игровых форм, диапазон 100–30000 faces по README [6]; 4000 — пример цели для стены; реальные цели по роли (500–5000 обычно) в OPTIMIZATION_FIRST.md, уточнять после аудита. Smart Topology только triangle; не задавать should_remesh/decimation_mode. Standard (6-lite или 7.1) — при обоснованной нехватке формы/силуэта, после проверки совместимости и цены. Не использовать Ultra и дополнительные платные операции по умолчанию. Для geometry-only не запускать refine/retexture, не отправлять texture_prompt. У Image-to-3D явное отключение текстур, если отсутствует такое управление — не запускать без проверки. Проверять тариф, кредитный лимит и схему непосредственно перед вызовом.

## 5. Подготовка изображений
По [7–9], один объект на кадр, видимый целиком, чистый фон, чёткие края, равномерное освещение; для нескольких видов один и тот же объект, масштаб и стиль, действительно разные ракурсы (передний, боковой, задний, при необходимости второй боковой). Не смешивать разные скалы. Один чёткий вид лучше нескольких несогласованных. Multi-view веб-интерфейса и API могут иметь различные ограничения; сверить API и MCP для установленной модели. Не передавать схему маршрута, общий кадр ущелья, разметку и подписи, коллаж с несколькими объектами или скриншот старого грейбокса. Для навеса предпочесть ракурс, где виден низ, и отдельный боковой вид; для обрыва — профиль. Референсы создавать отдельно только если разрешено и нужно, не запускать платную 2D-генерацию без отдельного бюджета. При необходимости простой локальный объёмный эскиз служит только входом Meshy, не финальной геометрией. Не использовать чужой ассет/фото как вход без прав на такое использование. Не загружать частные материалы без разрешения. Проверить SHA-256 и происхождение; не хранить подписанные URL или base64 в журнале. Image Enhancement только при объективно плохом входе и после проверки эффекта/доступности; по умолчанию не нужно. В image-режиме геометрия задаётся картинкой; текстовый промпт из библиотеки не подставлять в texture_prompt.

## 6. Исправление ошибок по результату (не больше двух попыток на shape_key)
| Дефект | Коррекция |
|---|---|
| Получилась целая гора с землёй вместо стены | Начать с single cliff wall module; убрать mountain landscape и атмосферу; добавить no ground plane |
| Округлые валуны | Сделать главным признаком broad angular fractured bedrock planes; убрать smooth и boulder |
| Навес с колоннами, заполненный низ | Уточнить thick attached root, open space beneath projection, no support columns; при необходимости разрешённый профиль |
| Скала похожа на шестиугольную колонну | Убрать geometric/hexagonal; irregular asymmetrical layered planes, uneven ridge |
| Неподходящая толщина или угол | Уточнить сравнительные пропорции, проверить поворот и масштаб; если форма всё ещё не решается, использовать профиль |
| Мелкие плавающие куски | Упростить описание; local mesh cleanup если не нарушает силуэт, иначе одна обоснованная повторная попытка |
| Избыточная детализация | Убрать micro detail, использовать broad readable planes и lower target_polycount, если нужно повторять |
| Цвет/материал не подходят | Не повторять генерацию; локальная коррекция |

Первая попытка: текст или заранее обоснованный image. После результата определить один главный дефект, изменить только соответствующее требование или канал. Не считать бесплатные повторы веб-плана применимыми к API. При сетевом сбое не повторять создание задачи до сверки ID (MESHY_WORKFLOW). Второй неудачный результат → блокер либо другой готовый допустимый ассет. Не обходить лимит созданием новых shape_key для того же слота.

## 7. Приёмка формы до материала
- Сохранить ID, фактический prompt, параметры, source hash и стоимость. Дождаться SUCCEEDED, скачать FBX, проверить staging и импорт согласно MESHY_WORKFLOW.
- Осмотреть front/side/back/top и clay с реальной камерой; проверить крупный силуэт, согласованность геологии, толщину, стыки, основание, обратные стороны, отсутствие лишних частей. Проверить заполнение измеренного слота и отсутствие пересечения пути, камеры, важных якорей, открытого обрыва. Никаких старых стен под новым ассетом.
- Проверить normals, UV или пригодный world-space материал, фактические tris, LOD, коллизии. Сравнить маршрут с baseline; пройти пешком/кувырком. Не исправлять геймплей ради ассета. Только после этого использовать наши холодные материалы и снег. Принятый меш — в локальную библиотеку, с GUID/hash и источником. Не объявлять PASS без Unity.

## 9. v4.4 — экономичная форма вместо микродетализации
Если фразы ещё нет в выбранном шаблоне, добавлять `Low-poly game environment mesh, broad readable planes, simplified fractures, no microgeometry, no detached fragments.` (в пределах фактического лимита prompt). Это просьба, не гарантия tris. Использовать низкий target по роли, triangle topology и только поддерживаемые схемой поля. Сравнить actual triangles после импорта; если не подходит — локальная децимация на копии, LOD и проверка силуэта. Не запускать повтор ради красоты. `OPTIMIZATION_FIRST.md` — обязательный контракт, не принимать тяжёлую модель без его gate.
