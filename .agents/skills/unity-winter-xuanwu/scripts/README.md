# Editor tools: установка и безопасное использование

Не запускаются автоматически. Не импортируют сторонние пакеты, не создают бой, не меняют pipeline. C# исходники рассчитаны на Unity 6.x, не скомпилированы в этом окружении. Сначала проверить компиляцию на копии проекта. Копировать только `unity-editor/*.cs` в `Assets/Editor/XuanwuTools/`; HLSL отдельно лишь при необходимости. Не ставить всё в runtime. Открой одну рабочую сцену (без additive сцены) `Assets/.../Xuanwu_Work.unity`; модифицирующие scene tools сверяют точный scenePath и имя. Оригинальная сцена/данные неизменны. Undo не удаляет созданные .asset файлы: журналировать и убирать неиспользуемые копии вручную. Не вызывать в Play Mode кроме Capture.

## Как работать
1. `01 Scene audit`: read-only отчёт в `XuanwuReports/` вне Assets. Снять реальную камеру и контроллер, не предполагать Cinemachine. Отчёт только активной сцены, не всех загруженных.
2. Заполнить `route-config.json`: точки по поверхности world XYZ в порядке пути, не высота камеры. `halfWidth`, `shoulder`, `step` в метрах. `maxStep` здесь максимально допустимая разница высот соседних samples (не literal stepOffset; калибровать для угла/шага). `groundMask` и `obstacleMask` — целые bitmask существующих слоёв; не ID слоя. Настроить так, чтобы ray не попал в потолок, а capsule не задевала пол; если общие слои, разбирать false positives. `castUp/Down` короткие, вокруг известной высоты пола. protectedAreas: массив объектов `{"center":{"x":0,"y":0,"z":0},"size":{"x":1,"y":1,"z":1}}`; XZ-прямоугольники полной ширины size, Y не используется. Отметить разрывы и исключённые области; проверить round-trip JsonUtility в своей версии. Заполнить actual, шаблон намеренно не выполняется. В сложных перегибах разбить путь на участки. Валидация выборочная: не заменяет контроллер/камеру/roll.
3. `03 Shape terrain`: выделить Terrain активной сцены, заполнить config. Вычисляет предлагаемую карту высот, показывает число изменяемых samples; только после подтверждения клонирует TerrainData и применяет. Не использовать в местах где route может перекрыть расщелину; защищённые области обязательны. Режим не создаёт holes, не строит стены. При повторном запуске тот же результат обычно близок, но shoulder blend может продолжать изменять старый рельеф; не повторять вслепую. Для нового прохода брать baseline copy и проверять.
4. `04 Place prefabs`: JSON с placements: `id`, `prefab` (Assets/...prefab), `position`, `euler`, `scale` (world units, positive). Root identity transform; существующий ID пропускается, не обновляется. Отдельно проверять положение, safe corridor и mesh backs. Undo группируется; только prefab, не импортирует модели.
5. `05 Audit selected models`: выбрать prefab/model в Project или объект в Hierarchy; выдаёт mesh/material/texture inventory. LOD counts и tris относятся к mesh, не к кадру.
6. `06 Prepare selected copied textures`: только копии внутри Assets/XuanwuGenerated; ограничивает maxTextureSize, включает mipmaps. Не меняет автоматически data/sRGB/normal и platform override. Не запускать на lightmaps, UI или authored masks.
7. `07 Normalize selected copied rock materials`: только копии .mat; K1 mild tint и roughness. K2/K3 сначала обработать BaseColor (Python) и вручную убрать растения. Не использовать на снегу, metal или чужих shader properties без проверки.
8. `08 Paint slope snow`: выбранный Terrain, ровно 2 TerrainLayer, индексы 0/1, пороги. Клонирует TerrainData, заменяет всю splat map. Не запускать на уже вручную нарисованных слоях. Для скал-мешей отдельная Shader Graph функция, не обязательна.
9. `09 Build backdrop`: заполнить id, материал, world position, width/depth/height (м), seed. 33×33 vertices/2048 tris; геометрическая оболочка для тумана, без коллайдера. Не готовая фотореалистичная гора. Не размещать над проходом; проверить открытые края.
10. `10 Performance inventory`: статический inventory; реальный CPU/GPU/batches/visible tris измерять Unity Profiler/Frame Debugger. Заполнить performance-report.
11. `11 Capture`: только Play Mode, текущий Game View; дождаться создания PNG и проверить файл; не автоматически переставляет camera. Записать позу/FOV; использовать одинаковые ракурсы.
12. `12 Material lab`: выбрать 1–12 .mat в Project; создаёт additive unsaved lab со сферами, плоскостью, камерой, neutral key. Сохранить отдельно, закрыть исходную сцену для сравнения. HDRP/URP exposure и Volume выставить вручную. Не меняет исходные материалы.

## Python
`python scripts/asset-processing/catalog.py --role wall --family layered --limit 5` — короткий список; `--rebuild` пересоздаёт MD/CSV/HTML/compatibility из JSON. `python .../recolor.py --profile K2 --out Output path/Rock_BaseColor.png` — dry run; добавить `--apply` после проверки. Требования Pillow, numpy. Использовать отдельные явные файлы, не массовый glob всего проекта. Сохраняет альфу, не перезаписывает исходник, только 8-bit RGB/RGBA sRGB PNG output. Не выполняет PBR packing/геометрическую очистку.

## Smoke tests в Unity (обязательны перед реальной сценой)
- Compile all; Console без ошибок. New scratch `Xuanwu_Work_Test.unity`, Terrain 33×33, plane, простая капсула, две копии материалов. SceneGuard должен отклонять другое имя/путь/Play Mode.
- Shape Terrain: неверный config отклонён, затем 2 точки и protectedArea, подтвердить изменения только в копии, исходный TerrainData неизменен, Undo восстанавливает ссылку. Сверить bounds serialization и samples.
- Route: flat plane → no ground after removing plane → obstacle cube on corridor → excessive slope; проверить no false PASS и сравнить с Play Mode.
- Placement: пустой/дублирующий ID отклонён; один prefab → повтор не создаёт копию; Undo удаляет root/instance. Не удаляет пользовательские объекты.
- Snow: 2 слоя, веса суммируются до 1; >2 layers rejected; original untouched.
- Import/Material: оригиналы вне generated folder отклонены; K1 копия изменяется только после подтверждения.
- Backdrop: один ID, повтор отклонён, отсутствует collider; asset survives reload.
- Lab: сохранить отдельно, проверить, что исходная сцена не изменилась. Capture: реальный PNG. Performance: inventory явно отличается от frame stats.
